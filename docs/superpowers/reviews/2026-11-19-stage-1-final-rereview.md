### New Breakage in the Fix Diff

No Critical or Important breakage found. Checked specifically and found clean: no deadlock or stuck native thread on cancel/quit/close while paused (cancel wakes the wait; quit cancels all; pool threads are background); pause state is per operation and does not leak to the next file; paused time is excluded from speed/ETA; flags are cleared only on the part path and never through a link; the lock is re-applied only after the final rename; a failure after the file is in place skips the item, so a move keeps the source; an existing (merged) destination folder's metadata is not overwritten; double close is ignored while the question is open or the stop is awaited; no file is ever left half-written under a real name by the bounded wait.

Minor:
- **Moving a Finder-locked file to another volume leaves it in both places** with an access-denied question (`MoveOperation.cs:138-148` after `CopyEngine.cs:499-503`). Safe (nothing lost; the implementer chose not to unlock the user's source), but it is not written in the checklist or known limitations. Within one volume a locked file cannot be moved at all (rename refused) — unchanged behaviour.
- **During the wait for stopping operations (up to 10 s) the main window is usable and shows nothing** (`MainViewModel.cs:288-299`). Normally this is milliseconds. On a slow volume the user could start a new operation in that time; it would be killed by the close without a question. If the wait times out, a `.tandem-part` can remain, while the checklist says such files remain only after a crash (`stage-1.md:319`).
- **Retry after a failed flag re-apply asks a conflict question about the file just copied** (`CopyEngine.cs:499-503`, then `:275-285`): the file is already in place, so the retry sees an existing destination. Confusing wording, no data risk. Needs a destination that refuses `lchflags`; exFAT accepted it in my experiment.
- **Folder metadata failures are now one question per folder** (`CopyEngine.cs:441-453`). exFAT checked: no errors. SMB and other network volumes are unverified; "Skip all" is offered.
- **Unverified on screen:** the native Cmd+Q / Dock Quit path into Avalonia's shutdown request, and the quit question opening while another modal dialog (a conflict question) is already open — two modal dialogs on one owner (`DialogService.cs:62-67`).

**Fix wave:** All in-scope findings addressed, no new Critical/Important breakage.

Known issues worth telling the customer (all Minor):
- A Finder-locked file moved to another disk is copied there but also stays in the original place, with an "access denied" question, because Tandem does not unlock your file.
