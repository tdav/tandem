# Этап 2 — отложенные замечания (что может подождать)

Собрано из журналов выполнения этапа 2 (основного и двух параллельных направлений — поиска и архивов) и из
итоговой проверки этапа (раздел «может подождать»). Каждый пункт — мелкое замечание, которое проверка задачи или
итоговая проверка отметила и которое сознательно не исправлялось в этапе 2: ни одно не теряет данные и не мешает
приёмке. Известные ограничения, о которых знает пользователь, описаны отдельно в `docs/checklists/stage-2.md`.

## Архивы
- Упаковка в tar и tar.gz отклоняет весь архив, если имя файла или папки начинается или кончается пробелом (библиотека обрезает пробелы). Лучше пропускать такие имена по одному и перечислять их среди пропущенных, как имена с «:».
- Если метку карантина не удалось поставить, ошибка пишется в журнал для каждого файла; достаточно одной записи на операцию.
- Пока упакованный архив читается обратно для сверки со списком записанного, окно прогресса не показывает хода работы.
- Нет теста, который проверяет, что в собранном приложении перенос метки карантина действительно подключён (сейчас он проверен по частям).
- Надпись «Запись архива…» на мгновение появляется и для операций, которые архив не меняют (например копирование из zip).
- Перезапись zip после добавления файлов нельзя отменить: «Отмена» не прерывает запись (исходный архив при этом остаётся целым).
- Один и тот же архив, открытый по двум написаниям пути (например с разным регистром букв), открывается дважды, как два разных архива.
- Временные копии файлов, открытых из архива клавишей Enter, живут до выхода из приложения; второй запущенный экземпляр приложения удаляет их у первого.
- После правки zip сам файл архива теряет свои расширенные атрибуты и теги Finder (переносятся только записи внутри).
- Чтение RAR и 7z с зашифрованным списком файлов: уточнить вид ошибки при неверном пароле и проверить содержимое RAR, когда появятся тестовые архивы.
- Определение формата архива читает файл синхронно внутри фоновой задачи (сейчас вызывается не из потока интерфейса, поэтому не мешает).
- Проверка «архив ли это» по содержимому (Alt+F9 на файле без расширения архива) не перехватывает непредвиденные ошибки так же, как остальные пути; она читает список архива ещё до диалога и без индикатора; двойное Alt+F9 во время проверки открывает два диалога; при сбое запуска приложения закрытый объект открытых архивов остаётся зарегистрированным.
- При неудаче внутренней записи после того, как вложенный архив уже записан, а внешний — нет, вложенный архив до следующей сверки показывает отменённое состояние.
- Комментарии папок внутри zip при правке не сохраняются (ограничение библиотеки).
- Отменённая запись без признака отмены сообщается как «отменено»; ошибка записи теряется, если сама операция тоже завершилась ошибкой; ошибка закрытия пакетной записи не пишется в журнал приложения, и более поздняя такая ошибка затирает более раннюю.
- Путь внутрь архива, подставленный в строку пути и подтверждённый без изменений, читается как путь на диске и не открывается; обработка незарегистрированного источника при загрузке панели неодинакова.
- Чтение из старого снимка архива после его перезагрузки в редком случае даёт «сырую» системную ошибку вместо понятной.
- Закрытие потока чтения файла из архива при ошибке может не освободить часть ресурсов.
- Файлы с кодом архивов слишком велики (около 1000 и 800 строк) — стоит разнести вспомогательные части по отдельным файлам.
- Тесты: нет проверки «вверх» по цепочке zip в zip; отмена открытия архива проверена только до вызова; тест опасных путей ловит ошибку лишь на уровне источника; тест упаковки на диске проверяет имена только через `unzip -t`; один путь чтения при упаковке не проверяет паузу (сейчас не используется); тест прав временной папки ничего не проверяет при запуске от root; одна проверка ожидания пакетной записи использует фиксированную задержку 200 мс.

## Поиск
- Поиск от корня диска `/` проходит `/System/Volumes/Data` дважды (это тот же том данных, который macOS показывает и под корнем), поэтому результаты и время удваиваются для этой части.
- Панель кнопок недоступна, когда активная панель показывает результаты поиска или архив, — программам нужны настоящие пути. Это продуктовое решение; его можно пересмотреть (например разрешить кнопки, которым пути не нужны).
- Фильтр размера для ссылки на файл смотрит на размер самой ссылки, а не файла.
- Кусок длинной строки, который кончается символом `\r` перед `\n`, проверяется вместе с `\r`.
- Строки с одинаковыми именами в результатах могут меняться местами при обновлении.
- Список панелей-целей пересобирается при каждой проверке доступности команд; таблица удалённых списков найденного растёт на одну запись за каждый удалённый список (ничтожно мало).
- Английский текст сообщения о пределе результатов звучит неуклюже.
- Тесты: ограничение частоты обновлений (10 в секунду) не проверено без подмены часов; не проверен признак для файла ровно 64 КБ; тест отмены опирается на порядок вставки; в нескольких тестах неудобная форма проверок.

## Просмотр и правка
- Файл UTF-32 с меткой BOM читается как UTF-16LE.
- Текст в UTF-16 без метки BOM и без русских букв показывается как двоичный; KOI8-R и CP866 не распознаются автоматически (только ручной выбор).
- Декодер картинок не ограничивает число пикселей: очень большая по размерам картинка может занять много памяти.
- В быстром просмотре отказ от пароля архива действует, пока панель не сменит папку; правило выбрано из нескольких вариантов, и его границы стоит уточнить с заказчиком.
- На дисках без учёта регистра один файл, открытый как `/tmp/A.txt` и как `/tmp/a.txt`, может получить два окна редактора.
- Ошибка самого диалога подтверждения сохранения не перехватывается; если файл удалили, пока редактор задавал вопрос, сохранение заканчивается ошибкой (понятной).
- Ошибки при закрытии просмотра молча проглатываются; одна защитная ветка просмотра недостижима, и это стоит описать в коде.
- Длина файла в просмотре ждёт, пока закончится другое чтение (описано в коде); в тесте согласованности листания нет окна точно на границе смены правила деления строк.

## Настройки
- Во время записи сочетания системные сочетания (например Cmd+Q) поглощаются: команда не выполняется и пользователю ничего не сообщается.
- Числовое поле молча обрезает значение до допустимого предела; переназначения для неизвестных команд, записанные последними, в более новой версии могут перебить новые.
- Для команды без сочетания на панели F-клавиш остаётся пустой промежуток вместо подписи клавиши.
- Ошибка в обработчике сбоя сохранения может скрыть исходную ошибку уведомления об изменении.
- Список файлов не отписывается от событий при удалении из окна; тема применяется только через главное окно.
- Кнопка с `open` разбирает имя `%n`, начинающееся с «-», как ключ программы; фоновый дочерний процесс кнопки может получить SIGPIPE; наблюдатели запуска считают, что запуск никогда не завершается ошибкой.
- Подписи вариантов в настройках кешируются; имя класса файла настроек `SettingsFile` совпадает с другим именем в коде; задержка индикатора загрузки не проверена на сбой.
- Тесты: не проверены ветки разбора неверных чисел и перечислений в файле настроек; часть тестов окна настроек не следует общим правилам оформления.

## Общее
- Движок копирования по-прежнему получает источники и операцию отдельно от планировщика; в тестах путь проверяется по началу строки (`/a` совпадает и с `/ab`).
- Переименование с изменением только формы записи Unicode проверено вручную написанным тестом, а не общим набором тестов источника на настоящем диске; в коде не описано, что без слоя macOS такие переименования не работают.
