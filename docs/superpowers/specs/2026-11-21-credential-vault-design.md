# Зашифрованное хранилище подключений Tandem

## Назначение

Один переносимый файл хранит сохранённые подключения FTP, FTPS, SFTP и SSH. SSH-консоль открывается из самостоятельного профиля SSH или использует ту же запись, что и панель SFTP. Запись включает идентификатор, имя, адрес сервера (DNS или IP), порт, логин, протокол, способ входа и настройки подключения. По выбору пользователя она хранит пароль, байты закрытого SSH-ключа и ключевую фразу. Пароль и ключевая фраза необязательны. Анонимный FTP не требует секрета.

## Выбор подхода

- Оставить системную связку основной и добавлять зашифрованный экспорт. Удобно для обратной совместимости, но экспорт устаревает после изменений и оставляет два рабочих источника.
- Использовать файл с ключом, привязанным к связке macOS. Удобно на одном Mac, но один файл недостаточен для открытия на другой системе.
- Использовать файл с пользовательским мастер-паролем как рабочее хранилище. Этот вариант выбран для реализации. Файл можно перенести целиком, а совместимый потребитель сможет прочитать его по формату ниже. Цена переносимости — разблокировка при каждом запуске, когда понадобятся подключения.

## Поведение приложения

- До явного создания хранилища действует прежний режим. Действие в менеджере подключений предлагает создать хранилище и дважды ввести мастер-пароль длиной от 12 символов. Tandem переносит сохранённые профили, доступные секреты службы Tandem и байты указанных ключевых файлов. Ошибка чтения ключа или связки останавливает перенос целиком. Отсутствующий пароль остаётся отсутствующим. Создание файла и переключение Tandem происходят после сбора записей. Исходные записи связки, старый JSON и файлы ключей сохраняются для ручного восстановления.
- При последующих запусках менеджер подключений запрашивает мастер-пароль. Записи открываются только после проверки целостности и расшифровки. Отмена и неверный пароль оставляют файл закрытым. Если хранилище существует, приложение использует его для чтения и записи и не обращается за секретами к старому хранилищу. После разблокировки список подключений обновляется, включая боковую панель и доступность SSH-консоли.
- При редактировании профиля сохраняются поля подключения и разрешённые секреты одной транзакцией. Для профиля с ключом Tandem использует сохранённые байты даже при отсутствии исходного файла. При выборе другого ключевого файла его содержимое читается через локальный файловый источник. При удалении профиля из активного хранилища удаляется вся запись. Сохранение по запросу при успешной аутентификации также обновляет хранилище. Поля редактирования секретов остаются пустыми при открытии формы.
- Единственная рабочая копия по умолчанию находится в `~/Library/Application Support/Tandem/credentials.tandemvault`. Для чтения в другой системе нужны файл, совместимый читатель и мастер-пароль. Доверенные ключи серверов и сертификаты по-прежнему хранятся в `known-hosts.json` на каждой машине.
- Ключ расшифровки держится в памяти до выхода из приложения. Сам мастер-пароль не сохраняется. Интерфейс не показывает расшифрованный файл и не создаёт открытых копий. Система назначения сама отвечает за хранение расшифрованных данных после чтения. Сброс мастер-пароля, облачная синхронизация и передача файла третьим лицам не входят в эту работу.
- Перенос собирает снимок настроек из запущенного экземпляра. Изменения, записанные параллельным экземпляром в старое хранилище во время переноса, могут остаться только в старом хранилище.

## Формат v1

Двоичное представление, поля подряд, без пробелов и разделителей.

| Смещение | Содержимое |
|---|---|
| 0–7 | ASCII `TANDVLT1` |
| 8–23 | Случайная соль, 16 байт |
| 24–35 | Случайный nonce, 12 байт, новый при каждой записи |
| 36–51 | Тег AES-GCM, 16 байт |
| с 52 | Шифртекст |

Ключ размером 32 байта выводится из мастер-пароля в UTF-8 и соли алгоритмом PBKDF2-HMAC-SHA256 с 600 000 итераций. Шифрование AES-256-GCM, AAD — первые 36 байт файла. Полезная нагрузка — UTF-8 JSON с объектом `{"entries":[...]}`. У каждой записи поля `profile`, `password`, `privateKey` и `passphrase`. `privateKey` — Base64 исходных байтов файла. Отсутствующий секрет — JSON `null`, пустой сохранённый пароль — пустая строка. У `profile` поля `id`, `name`, `protocol`, `host`, `port`, `user`, `auth`, `privateKeyPath`, `initialPath`, `passiveMode`, `nameEncoding`. Протоколы — `ftp`, `ftpsExplicit`, `ftpsImplicit`, `sftp`, `ssh`. Для чтения файла с записями `ssh` требуется читатель, поддерживающий это значение. Режимы входа — `password`, `privateKey`, `anonymous`. Закрытые ключи и путь хранятся внутри шифртекста. Путь служит подсказкой для интерфейса и не нужен совместимому читателю для использования ключа.

Реализация ограничивает размер файла 32 МиБ, а одного исходного файла ключа — 1 МиБ. Запись идёт через временный зашифрованный файл в том же каталоге, с атомарной заменой и правами владельца на Unix. Запись прекращается, если другой экземпляр изменил или удалил файл после разблокировки. Неверный пароль и повреждённый тег дают одинаковую ошибку для интерфейса. Содержимое и секреты не попадают в ошибки и диагностические строки моделей.

## Приёмка

Перенос и запуск с существующей конфигурацией покрываются тестами с поддельной связкой ключей. Тесты формата проверяют запись и чтение кириллицы, IPv6, пароля и ключа, отклонение неверного мастер-пароля, изменение байта файла, сбой сохранения и конфликт экземпляров. Проверка интерфейса использует синтетические данные. Рабочие записи пользователя в рамках разработки не переносятся.
