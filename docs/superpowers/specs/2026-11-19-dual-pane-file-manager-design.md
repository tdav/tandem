# Двухпанельный файловый менеджер для macOS — спецификация

Дата: 2026-11-19. Статус: на утверждении (проверка независимым читателем пройдена).
Рабочее название: **Tandem** (решение автора спецификации; окончательное имя выбирается до этапа 4).

Пометка «(реш.)» означает решение автора спецификации, а не заказчика — заказчик может его изменить.

## 1. Замысел

Заказчик хочет полноценный двухпанельный файловый менеджер в жанре Total Commander: в первую очередь
для собственной ежедневной работы на Mac с Apple Silicon, а если получится хорошо — для публикации в
Mac App Store.

Это собственное приложение того же жанра, а не копия: логика работы (две панели, клавиатура, F-клавиши,
операции между панелями) та же, но название, иконки и точный внешний вид оригинала не воспроизводятся.

## 2. Цели, не-цели, анти-цели

**Цели**

- Заменить Finder в повседневной работе с файлами: всё основное делается с клавиатуры.
- Реализовать все десять групп функций (раздел 6) в четыре этапа; после каждого этапа — рабочая программа.
- Работать на macOS, Apple Silicon (arm64).
- Быть готовым к Mac App Store: включение песочницы на этапе 4 не должно требовать переписывания ядра.

**Не-цели**

- Сборки под Windows, Linux и Intel-Mac. Архитектура их не запрещает, но они не собираются и не проверяются.
- Совместимость с плагинами Total Commander (WCX/WFX/WLX) и собственная система сторонних плагинов.
- Облачные диски через их API (Dropbox, Google Drive и т. п.). Папки, смонтированные системой, работают как обычные.
- Встроенный эмулятор терминала.
- Поиск внутри архивов и на сетевых источниках.
- Создание архивов RAR; докачка прерванных сетевых передач.
- Операции, требующие прав администратора (запись в системные папки с запросом пароля): показывается понятная ошибка, повышения прав нет (реш.).
- Разрезание/склейка файлов, кодирование, запись дисков и прочие редкие утилиты оригинала.

**Анти-цели** (провал, даже если всё остальное работает)

- Потеря данных. Никакой молчаливой перезаписи; перенос между томами = копирование, проверка, и только затем удаление источника; прерванная операция не оставляет испорченного целевого файла под настоящим именем.
- Зависание интерфейса во время файловых операций или чтения больших папок.
- Использование названия, иконок или оформления Total Commander.

## 3. Ограничения

- C#, .NET 11 (SDK 11.0.100 установлен), Avalonia 12.x (на дату написания стабильная 12.1.6).
- Машина разработки: macOS 27, arm64, Xcode 27.2. Минимальная поддерживаемая версия macOS — 14 (реш.; строитель проверяет, что её поддерживают .NET 11 и Avalonia 12, иначе поднимает до минимально поддерживаемой).
- Mac App Store требует песочницу: приложение видит только папки, к которым пользователь явно дал доступ; подгрузка стороннего кода запрещена.
- Для этапа 4 нужна учётная запись Apple Developer заказчика (подпись, нотаризация, отправка в магазин). Это действия заказчика; спецификация готовит сборку и инструкции.
- Спецификацию и планы пишет модель Fable 5.2, реализацию выполняет Opus 5.5 (требование заказчика).

## 4. Подходы

Рассмотрены три варианта внутреннего устройства:

1. **Простое приложение** — панели обращаются к диску напрямую. Быстрее всего на старте, но архивы, FTP и песочница потребовали бы переделки ядра.
2. **Слои с единым «источником файлов»** — панель работает с общим интерфейсом; локальный диск, архив и сервер — его реализации; движок операций один; всё специфичное для macOS вынесено в отдельный модуль. Старт чуть дольше, зато архивы и сеть добавляются без переделок, копирование «из архива на сервер» получается само собой, песочница включается в одном месте, ядро тестируется без окна.
3. **Плагины с первого дня** — каждый источник и инструмент как подгружаемый модуль. Максимальная расширяемость, но App Store запрещает подгружать сторонний код, а заказчику расширяемость сейчас не нужна.

**Заказчик выбрал вариант 2**: выбраны все группы функций, включая архивы, сеть и публикацию — именно для них этот вариант окупается.

## 5. Архитектура

### 5.1. Проекты решения (реш.)

| Проект | Назначение | Зависит от |
|---|---|---|
| `Tandem.Core` | Модель путей, интерфейс источника файлов, локальный источник, движок операций, поиск, инструменты, настройки. Без интерфейса и без вызовов macOS | — |
| `Tandem.Archives` | Источник «архив» (SharpCompress) | Core |
| `Tandem.Net` | Источники FTP/FTPS (FluentFTP) и SFTP (SSH.NET) | Core |
| `Tandem.Platform.Mac` | Всё специфичное для macOS: корзина, Quick Look, «Открыть в», теги, тома, связка ключей, доступ к папкам в песочнице | Core |
| `Tandem.App` | Интерфейс на Avalonia, MVVM (CommunityToolkit.Mvvm) | все |
| `tests/*` | xUnit-тесты на Core, Archives, Net; тесты моделей представления через Avalonia.Headless | — |

`Core` обращается к возможностям платформы только через интерфейсы (например, `ITrash`, `IFileAccessBroker`, `ISecretStore`, `IVolumeWatcher`), реализованные в `Platform.Mac`. Это и есть место, где позже включается песочница.

### 5.2. Источник файлов

Единый интерфейс, с которым работают панели и движок операций. Смысл (точные сигнатуры — за строителем):

- перечисление содержимого папки потоком (асинхронно, с отменой), чтобы большие папки появлялись по мере чтения;
- сведения об элементе: имя, тип, размер, даты, права, скрытость, символическая ссылка;
- открытие на чтение и на запись как поток; создание папки; удаление; переименование/перенос внутри источника;
- объявление возможностей: только чтение, поддержка корзины, прав, быстрого переноса и т. п. Интерфейс отключает недоступные команды по этим признакам;
- необязательные «быстрые пути»: локальный источник копирует средствами системы с сохранением метаданных, расширенных атрибутов и с клонированием на APFS, а не побайтно через потоки.

Путь = источник + путь внутри него. Источники вкладываются: архив, лежащий на диске или на сервере, открывается как источник поверх родительского.

Источники: локальный диск (этап 1), результаты поиска (этап 2), архив (этап 2), FTP/FTPS и SFTP (этап 3).

### 5.3. Движок операций

Один на все источники. Операции: копирование, перенос, удаление, упаковка, распаковка, синхронизация.

- Выполняется в фоне; интерфейс не блокируется. Окно прогресса: текущий файл, файлов и байтов сделано/всего, скорость, оставшееся время. Пауза, отмена, «в фон».
- Очередь: несколько операций одновременно либо по очереди (выбор пользователя в диалоге; по умолчанию новые встают в очередь, если затрагивают тот же том) (реш.).
- Конфликт имён: спросить (по умолчанию) — перезаписать / перезаписать более старые / пропустить / переименовать / сравнить; «применить ко всем».
- Ошибка на элементе: повторить / пропустить / пропустить все / прервать. По завершении — сводка пропущенного.
- Запись идёт во временное имя рядом с целью и переименовывается по завершении (там, где источник это позволяет).
- Перенос внутри одного тома — переименованием; между томами и источниками — копирование, затем удаление источника только для успешно скопированных элементов.
- Удаление: F8 — в корзину (локальный диск), Shift+F8 — безвозвратно с подтверждением. В источниках без корзины — только безвозвратно, с явным предупреждением.
- Символические ссылки по умолчанию копируются как ссылки, без захода внутрь (реш.).
- «Проверка» перед удалением источника при переносе (реш.): запись завершилась без ошибки и размер цели равен размеру источника. Дополнительно в диалоге копирования/переноса есть флажок «Проверить содержимое после копирования» (по умолчанию выключен): цель перечитывается и сравнивается с источником по хешу; при несовпадении элемент считается ошибкой и источник не удаляется.

### 5.4. Доступ к файлам и песочница

Все обращения локального источника проходят через `IFileAccessBroker`.

- Обычная сборка (этапы 1–3): посредник ничего не ограничивает. Отказ системы в доступе (защищённые папки macOS) показывается понятным сообщением с подсказкой про «Полный доступ к диску», а не падением.
- Сборка для App Store (этап 4): посредник запрашивает доступ к папке через системный диалог, сохраняет его между запусками (security-scoped bookmarks) и открывает/закрывает доступ вокруг операций. При первом запуске предлагается выдать доступ к домашней папке и томам.

Подпись на этапах 1–3 (реш.): на машине нет сертификатов подписи, а macOS привязывает выданные приложению разрешения на папки к подписи. Чтобы разрешения не сбрасывались после каждой пересборки, сборка подписывается постоянным локальным самоподписанным сертификатом; его создание — разовый шаг в плане этапа 1, выполняемый с согласия заказчика. На этапе 4 он заменяется сертификатами учётной записи Apple Developer.

Функции, невозможные в песочнице (произвольные команды в командной строке, запуск терминала), в этой сборке скрываются.

### 5.5. Хранение

- Настройки, раскладка клавиш, избранное, состояние панелей и вкладок, сохранённые подключения — файлы JSON в `~/Library/Application Support/<имя приложения>/` (реш.).
- Пароли и ключевые фразы — только в связке ключей macOS, никогда в файлах настроек.

### 5.6. Языки

Русский и английский. Строки интерфейса с первого этапа лежат в ресурсах, а не в коде (реш.: дешевле, чем выносить потом). Язык по умолчанию — язык системы, переключается в настройках.

## 6. Функции по группам

### A. Ядро (этап 1)

- Две панели; активная выделена; Tab переключает.
- Столбцы: имя, расширение, размер, дата, права. Сортировка по любому, щелчком по заголовку и с клавиатуры.
- Навигация: Enter — войти/открыть программой по умолчанию, Backspace — вверх, строка пути с возможностью ввести путь вручную.
- Выделение: Пробел и Insert-эквивалент, Shift+стрелки, выделить/снять по маске, инвертировать, выделить всё. Выделенные элементы показаны цветом.
- Быстрый поиск: набор букв переводит курсор на подходящее имя.
- F5 копировать, F6 перенести/переименовать, Shift+F6 переименовать на месте, F7 создать папку, F8 удалить; все через движок операций (5.3).
- Скрытые файлы — переключатель.
- Список томов с отслеживанием подключения/отключения, свободное место.
- Строка состояния панели: сколько выделено и какой объём.
- Ввод с клавиатуры (реш.): буквы в панели всегда идут в быстрый поиск; командная строка получает фокус по Cmd+L или щелчку, Esc возвращает фокус в панель. Путь панели редактируется по Cmd+Shift+G.
- Командная строка, панель F-клавиш, боковая панель и их переключатели в меню «Вид» входят в этап 1; панель кнопок с пользовательскими командами — в этап 2 (группа H).
- Список виртуализирован: папка на 100 000 элементов начинает показываться менее чем за секунду и прокручивается без рывков; чтение не блокирует интерфейс.
- Панель автоматически обновляется при изменениях в показанной папке.

### B. Навигация (этап 1)

- Вкладки в каждой панели: создать, закрыть, переключить, продублировать, закрепить.
- Избранные папки (быстрое меню) и история посещённых папок по каждой панели, назад/вперёд.
- При запуске восстанавливаются вкладки, пути, сортировка и размеры окна.
- Команды: показать в другой панели ту же папку, поменять панели местами.

### I. Интеграция с macOS (этап 1)

- Корзина системы; «Показать в Finder»; «Открыть в…» со списком программ.
- Quick Look по пробелу-эквиваленту (реш.: отдельное сочетание, так как Пробел занят выделением — см. 7.2).
- Перетаскивание файлов из Finder и в Finder и между панелями.
- «Открыть терминал в этой папке».
- Просмотр и изменение прав доступа (chmod), владелец — только просмотр.
- Теги Finder: показ и изменение.
- Системное меню приложения, светлая/тёмная тема по системной.

### C. Поиск файлов (этап 2)

- По имени: несколько масок, опционально регулярное выражение.
- По содержимому: текст, учёт регистра, регулярное выражение, выбор кодировки.
- Фильтры: размер, дата изменения, глубина вложенности, исключаемые папки.
- Результаты появляются по мере поиска; переход к файлу; «Показать в панели» — результаты как виртуальная папка, с которой работают все обычные операции.

### D. Просмотр и правка (этап 2)

- F3 — встроенный просмотр: текст (автоопределение UTF-8/UTF-16/Windows-1251, ручной выбор кодировки), hex, изображения. Файлы любого размера открываются без загрузки целиком в память.
- Панель быстрого просмотра: противоположная панель показывает содержимое файла под курсором.
- F4 — встроенный простой текстовый редактор (реш.: на основе AvaloniaEdit) либо внешний редактор, заданный в настройках.

### E. Архивы (этап 2)

- Вход в архив как в папку. Чтение: zip, tar, tar.gz/bz2/xz, 7z, rar. Запись (создание): zip, tar, tar.gz; 7z — если библиотека позволяет, иначе только чтение.
- Упаковать выделенное (Alt+F5-эквивалент), распаковать (Alt+F9-эквивалент), копирование из архива и в zip-архив обычным F5.
- Изменения внутри архива (реш.): только для zip — добавление, удаление, переименование, создание папки, перенос из архива, сохранение после F4. Каждое изменение пересобирает архив во временный файл и заменяет исходный только при успехе. Остальные форматы внутри — только чтение.
- Архивы с паролем: чтение zip и 7z с запросом пароля.

### H. Настройка (этап 2)

- Редактор сочетаний клавиш для всех команд; сброс к умолчаниям.
- Темы: светлая, тёмная, как в системе; цвета по типам файлов (по маскам).
- Настройка столбцов по панелям; размер шрифта и высота строк.
- Панель кнопок с пользовательскими командами (программа + параметры с подстановкой текущего пути и выделенных файлов).
- Переключатели вида (см. 7.1).

### F. Инструменты (этап 3)

- Групповое переименование: шаблон с именем, расширением, счётчиком, датой; поиск и замена, в том числе регулярным выражением; регистр; предварительный просмотр; отмена последнего переименования.
- Сравнение каталогов: пометить отличающиеся и уникальные файлы в обеих панелях.
- Синхронизация каталогов: сравнение по размеру и дате или по содержимому, список различий с выбором направления по каждому элементу, выполнение через движок операций.
- Сравнение файлов: текст бок о бок с подсветкой различий; двоичное сравнение.
- Контрольные суммы: создание и проверка CRC32, MD5, SHA-1, SHA-256.
- Размер папок: для папки под курсором и для всех сразу.

### G. Сеть (этап 3)

- FTP, FTPS, SFTP (пароль и ключ) как источник в панели.
- Менеджер подключений: сохранить, изменить, удалить; пароли в связке ключей.
- F4 на сервере (реш.): файл скачивается во временную копию, после сохранения предлагается загрузить его обратно.
- Все операции и просмотр работают через общий движок; обрыв связи — сообщение с возможностью переподключиться и повторить.

### J. Публикация (этап 4)

- Сборка в песочнице (5.4) со всеми ограничениями и первым запуском с выдачей доступа.
- Иконка приложения и окончательное название.
- Подпись, нотаризация, сборка для прямой раздачи (.dmg) и пакет для Mac App Store; пошаговая инструкция для заказчика по действиям в его учётной записи.
- Проверка обоих языков, экран «О программе», лицензии использованных библиотек.

## 7. Интерфейс

### 7.1. Главное окно

Заказчик выбрал **классическую компоновку с переключателями**:

```
┌──────────────────────────────────────────────────────────────┐
│ панель кнопок                                                │
├──────────────────────────────┬───────────────────────────────┤
│ тома · свободное место       │ тома · свободное место        │
│ вкладки                      │ вкладки                       │
│ /путь/активной/панели        │ /путь                         │
│ Имя        Размер   Дата     │ Имя        Размер   Дата      │
│ ..                           │ ..                            │
│ ▸ Projects  папка   12.11    │ ▸ 2025     папка    30.12     │
│   report.pdf 2,4 МБ 18.11    │   index.xlsx 88 КБ  10.11     │
│ выбрано 2 из 5, 2,4 МБ       │ выбрано 0 из 3                │
├──────────────────────────────┴───────────────────────────────┤
│ /путь > командная строка                                     │
│ F3 Просмотр │ F4 Правка │ F5 Копия │ F6 Перенос │ F7 │ F8    │
└──────────────────────────────────────────────────────────────┘
```

Через меню «Вид» независимо показываются и скрываются: боковая панель (избранное, тома, сетевые подключения), панель кнопок, строки томов, командная строка, панель F-клавиш. По умолчанию — как на схеме, боковая панель скрыта. Набор по умолчанию для сборки App Store решается на этапе 4.

Командная строка (реш.): `cd` меняет папку активной панели; остальные команды выполняются через zsh в текущей папке, вывод показывается во всплывающей области вывода.

## 8. Этапы и критерии готовности

Каждый этап получает отдельный подробный план перед началом и заканчивается собранным `.app` для arm64, который запускается двойным щелчком.

| Этап | Группы | Готово, когда |
|---|---|---|
| 1 | A, B, I | Заказчик день работает только в приложении вместо Finder: навигация, копирование, перенос, удаление в корзину, вкладки, перетаскивание, Quick Look. Папка на 100 000 файлов не тормозит. Прерванное копирование не портит данные |
| 2 | C, D, E, H | Поиск по имени и содержимому с выводом в панель; просмотр файла на несколько ГБ; вход в zip/7z и копирование из него; создание zip; переназначение клавиш и темы |
| 3 | F, G | Переименование 1000 файлов по шаблону с отменой; синхронизация двух папок; работа с SFTP-сервером как с панелью, включая копирование архив → сервер |
| 4 | J | Сборка в песочнице проходит проверку Apple (валидация пакета), подписанная сборка устанавливается из .dmg на чистом Mac |

После этапа 4 заказчик решает, отправлять ли в магазин.

## 9. Проверка качества

- Автотесты на `Core`, `Archives`, `Net`: движок операций (конфликты, ошибки, отмена посреди файла, перенос между источниками), маски, переименование, сравнение, синхронизация. Используются временные папки и источник «в памяти»; для FTP/SFTP — локальный тестовый сервер, поднимаемый в тестах (выбор средства — за строителем).
- Тесты моделей представления панели: навигация, выделение, сортировка, быстрый поиск.
- Реализация ведётся через тесты (сначала тест, затем код) для всего, что не является разметкой интерфейса.
- В конце каждого этапа — ручной список проверки по критериям раздела 8 на реальной машине.

## 10. Что оставлено строителю

- Точные сигнатуры интерфейсов, структура папок внутри проектов, имена типов.
- Выбор элемента управления для списка файлов (готовая таблица Avalonia или собственный виртуализированный список) — по результатам замера на 100 000 элементов.
- Способ вызова возможностей macOS (прямые вызовы системных библиотек или небольшая вспомогательная библиотека).
- Формат файлов настроек, механизм отслеживания изменений в папке, детали окна прогресса и диалогов.
- Точные версии пакетов (последние стабильные, совместимые с .NET 11).
- Порядок работ внутри этапа.

## 11. Решения автора спецификации (для проверки заказчиком)

1. Рабочее название Tandem.
2. Состав проектов решения и библиотеки: CommunityToolkit.Mvvm, SharpCompress, FluentFTP, SSH.NET, AvaloniaEdit, xUnit.
3. Минимальная macOS 14, только arm64.
4. Русский и английский с первого этапа.
5. Настройки в JSON в Application Support; пароли только в связке ключей.
6. F8 — в корзину, Shift+F8 — безвозвратно.
7. Символические ссылки копируются как ссылки.
8. Новые операции по умолчанию встают в очередь, если затрагивают тот же том.
9. Командная строка: `cd` — навигация, остальное — через zsh с областью вывода; в сборке для App Store скрыта.
10. Раскладка клавиш из 7.2, включая Cmd+Y для Quick Look.
11. Форматы архивов: чтение zip/tar/7z/rar, запись zip/tar/tar.gz.
12. Поиск внутри архивов и на серверах, докачка передач, операции с правами администратора — вне объёма.
13. Проверка при переносе — по размеру; проверка по содержимому — необязательный флажок.
14. Буквы — всегда быстрый поиск; командная строка по Cmd+L. Командная строка, панель F-клавиш и боковая панель — в этапе 1.
15. Изменять можно только zip-архивы; правка файла на сервере — через временную копию.
16. На этапах 1–3 сборка подписывается локальным самоподписанным сертификатом.
